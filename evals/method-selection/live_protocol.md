# Paratera 实际调用补充协议 v1

这是原 method-selection-v1 的供应商执行补充，不改变旧输入、标签、提示词、评分器或锁。
本轮仍为六个来源包、十二道内部合成开发题；不是正式同 token 预算试验或独立留出。

## 预先固定的执行边界

- 显式指定 `DeepSeek-V3.2-Instruct`；此前经认证的 Paratera 模型列表包含此 ID。
  一次 32 输出 token 的 JSON 探针先检查推理；探针不计入题目成绩，但计入总消耗。
- 最多 50 次生成请求、总计 150000 输入加输出 token；每请求默认 90 秒超时。
  6 次抽取、最多 36 次回答加探针，正常情况下最多 43 次。串行运行，不自动重试。
- 发送前按 system + prompt 的 UTF-8 字节数加 512 预留输入量，另预留固定输出上限。
  这是保守运营估计，不是模型 tokenizer，也不是严格数学上界或供应商账单硬限额。
  用供应商回传的实际 usage 扣减；缺失/矛盾或超过预留值立即停止后续请求。
  已发送请求无法撤销或保证供应商一定遵守输出上限。单次意外超额仍须如实保留。
- 供应商模型列表不含价格，本轮人民币花费记 unknown，不把 token 伪装成金额。
  若需要人民币硬限制，须先配置供应商账户限额并确认价格；本执行器不声称已经做到。
- 请求消息、temperature=0、max_tokens 原样对应冻结计划；不添加 JSON 修复、隐藏
  模型切换、额外推理参数或更强的结构组提示。不解析/采用 model owned_by 作为身份认证。
- 凭据仅从本机明确选择的 Paratera profile 或 `PARATERA_API_KEY` 读取。绝不从
  `ANTHROPIC_AUTH_TOKEN` 回退。密钥不写入计划/日志/命令，不上传真实用户收藏。

## 保存、恢复与失败

输出目录绑定模型、端点、预算、原实验锁、执行器及补充协议 hash。生成请求前写入
fsync intent，返回后写原始响应和校验收据；整轮持跨进程锁，避免同目录重复消费预算。
重新执行同目录时复用已完成请求，不把缓存复用计作新实验。只补从未发送的请求。

如果只剩 intent 没有结果，不能知道供应商是否计费，必须停止并人工检查，不能自动
补发。HTTP/传输/模型 ID/usage 错误保存后停止；不因失败而偷偷切换模型。正常 HTTP
返回但内容格式错误、length 或 content_filter 则按原协议留在失败分母内。

只保存返回正文和必要的状态/耗时/用量，不存请求 Authorization 或响应 headers。
如果供应商正文意外反射密钥，先明确脱敏并标记错误再落盘，不能宣称该正文未经改写。
收据 hash 检测意外修改，不提供远端身份认证，也不保证抵抗有文件写权限的伪造。

抽取阶段不读取问题或 gold。回答执行器只看到请求计划，不读取 gold；完整回答收齐
后才调用原评分器。原文组不依赖抽取成功，所有三组始终保留同一十二题分母。

## 结果边界与可复用部分

保留原始响应、构建卡片、三个真实上下文、逐题错误和用量。普通文本与结构卡共用
一次抽取，但部署成本分别承担完整构建费用；探针独立列出，不计入三组任务成本。
引用原文定位不等于语义支持。未回传的模型内部推理/账单细节不推测为零。

本补充协议和执行器在首个探针前冻结；调试改动需新输出目录/版本并保留原结果。
后续可以复用执行器、断点记录和指标，而不是复用旧分数证明改进。提示词、表示或
数据变更必须建新实验版本；已看过的开发题不能重新称为独立测试。
