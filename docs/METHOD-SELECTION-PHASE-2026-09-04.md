# 阶段交付：版本卡读取与方法选择实验准备

工作分支 `codex/retrieval-abstention`，起点 `ef2a272`。
阶段目标：完成版本卡状态/强度的最小消费契约，并使三组表示实验能够接收真实模型
响应。不是本轮证明产品成立或结构卡优于文本，也不自动运行付费模型。

## 1. 版本卡现在如何使用

内置 renderer 的完整、列表、compact、detailed、JSON 和字段筛选视图保留
`memory_status` 提示，不因只选择标题而隐藏争议状态。证据强度按 0–1 序数显示并
明确“不是概率”，不再渲染成 70% 这类像正确率的百分比。普通卡的旧接口保持兼容，
不会因一次读取被自动加入版本账本。

共享公共卡片投影把相同提示传给 CLI、HTTP、MCP。新增只读业务操作
`GET /memory/snapshot?topic=...`，仍使用现有 HTTP 访问保护和同一个服务；首次空库
快照不创建业务账本，损坏账本返回错误，不解释为空结果。已有 CLI memory snapshot
和 MCP sheaf_memory_snapshot 同样使用这一投影。

历史版本额外区分两个事实：

- `memory_status.state`：以读取时的账本 head 判断，旧版本可能已经 superseded。
- `memory_status.recorded_state`：该版本创建时记录的 active/contested/retired 状态。

因此旧 active 版本在被替代后，不再显示成当前仍有效；原账本和事件的历史状态不改写。
元数据缺失、状态/版本/分数互相矛盾时显示 unknown 并要求核对，不猜测为 active。

这是消费提示，不是授权或实时事实保证：单独 renderer 不重读账本，明确标记
`ledger_not_revalidated`。外部客户端、自定义模板仍可能忽略提示；本轮没有证明
Agent 会遵守提示，也没有把普通卡搜索和完整版本账本自动合并。

## 2. 方法选择实验的实际进展

[实验入口](../evals/method-selection/README.md)包含六个虚构来源包、十二个问题，
覆盖条件、版本、否定、缺失证据和冲突。全部是内部开发诊断，不是外部独立留出。

一次中立抽取生成 claim、conditions、exceptions、citations。两种卡复用相同内容：
普通文本使用真实 KnowledgeCard/renderer 输出，结构组使用最小 JSON；另有原文组。
这首先研究相同知识内容的表示差异，不是完整生产结晶系统的对照实验。

已经实现：

- 冻结输入、gold、协议和源码，请求计划与响应按 hash、模型 ID 严格匹配。
- 准备抽取/回答时不读取 gold；响应完整收齐后才加载评价标签。
- 原始构建响应、上下文、回答、usage、耗时及失败逐项保留；未知费用记 null。
- 原文组独立于抽取是否成功；超预算不截掉条件，不删除失败题目的分母。
- 逐题评价选择/弃答、方法、证据状态、引用唯一定位和必需来源覆盖。

尚未完成：真实模型执行器绑定、正式同 token 预算、语义蕴含裁判、独立留出及真实
效果比较。当前统一字符上限是离线预检约束，不是同 token 效果实验。调用模型前仍
需固定具体模型、tokenizer 和预算；本机检查未发现已配置的模型凭据。

不能把测试替身的响应计为实验结果。预检的输出是 `model_effects=not_run`，计划为
6 个抽取调用、最多 36 个回答调用，而不是“完成 42 次模型实验”。

## 3. 这阶段学到什么，下一步做什么

治理记录只有被消费才有产品意义。增加字段之后，还要检查列表、历史页和外部接口
是否保留其含义；尤其不要把“创建时 active”和“现在仍是有效版本”混在一起。

实验同样要沿实际信息流检查：抽取失败若连原文组也不运行，会人为削弱基线；只统计
成功调用会隐藏方法的失败成本。已经用测试覆盖这两点。

下一阶段优先绑定一个真实模型，先运行小规模开发试验，观察卡片构建损失、方法选错、
引用错误及费用。若普通文本已足够，就保留简单表示。正式比较需另冻同 token 预算
协议和新来源包留出，再决定是否进入增量维护效果与更广泛知识挖掘。

## 4. 验证记录

一次全量回归在 1100 passed / 20 skipped 后因运行期间源码变动，被实验源码一致性
保护正确中止。没有移除保护或修改历史锁；冻结实现后重新全量运行。
最终验证：

- 完整回归 **1486 passed, 20 skipped**（66.94 秒）。新增版本卡消费测试 30 项，
  方法实验流程测试 18 项，另扩展真实转移/历史服务测试验证 superseded 投影。
- Ruff、`git diff --check` 和核心离线评测通过。旧检索、表示与修复报告目录未修改。
- 方法实验预检通过；锁与最终源码、输入、gold、协议一致，模型调用数为零。
- 隔离构建通过，生成 sdist/wheel；在仓外临时 venv 安装 wheel，确认新版模块从该
  环境加载，compact 争议提示、HTTP snapshot 和 CLI version 烟测通过。安装烟测复用
  本机依赖，不宣称全新机器依赖兼容性已验证。
- 不推送远程、不发布包、不替换用户原有安装；未调用付费模型或读取真实用户知识库。
