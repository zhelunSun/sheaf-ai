# 方法选择 v2：证据类型与任务作用域

状态：看到 v1 失败后设计的内部合成前瞻诊断；不是独立外部留出、用户验证或论文结论。
一旦首个模型请求发出，输入、gold、协议、runner 和锁均不得修改。

## 假设

v1 观察到两种错误：一个方法的冲突污染了另一个方法；“不满足要求”被当成“来源冲突”。
本轮不再比较文本与 JSON 外观，而检验两个较窄的系统设计：

1. 抽取时把能力、要求、明确否定、测量结果、未报告维度分开，并区分适用条件、
   实际测量范围和明确未测范围；“未测”不能转写成“不支持”。
2. 回答前只保留当前任务 options 涉及的方法，以及适用于整个 bundle 的缺失报告事实。
   一个被排除方法的冲突不应影响当前方法；若当前方法自身证据冲突，仍须保留两侧。

## 比较组

- `raw`：完整原始来源。
- `all_facts`：一次中立模型抽取生成的全部原子证据 JSON。
- `scoped_facts`：相同事实、相同字段；确定性过滤只保留 `method_id in task.options` 或
  `method_id=null` 的 bundle 级事实。过滤不读 gold，也不按结果或状态筛选。

三组使用同一个模型、system、决策说明、temperature 和输出上限。任务 options 属于产品
运行时输入，三组都看得到；scoped 组没有答案标签或额外来源。原文不承担抽取成本；
任一事实组独立部署时承担完整构建成本。报告原生 token，不宣称三组输入同 token。

## 状态定义

- `supported`：相关证据覆盖全部任务条件，且不存在阻断该方法的相关冲突。
- `explicit_negative`：相关证据明确表明每个候选都违反至少一个要求；不是来源互相矛盾。
- `insufficient`：相关能力未报告、只在其他范围测过或证据不足，且没有直接反证。
- `conflict`：同一相关方法、版本、范围的证据相互不一致，以致不能决定。其他方法的
  冲突不能污染当前候选。

回答必须引用连续、可在原文唯一定位的片段。多个不连续句子使用多个 citation。证据不足
题若来源明确说“未报告/未测”，必须引用该片段；本数据没有要求模型凭沉默证明缺失。

## 隔离、指标与预算

抽取阶段只读取 method IDs 和 sources，不读取任务问题或 gold。回答计划可读任务，不读
gold；所有响应收齐并通过 ID/hash/model/usage 检查后评分器才读 gold。gold 与 inputs
物理分离；输入 schema 禁止 decision/evidence_state/required_sources/split/category。

逐题报告方法选择、状态、引用定位、必需来源覆盖和四者同时正确。抽取失败时 raw 仍运行；
三个组保留同一十二题分母。格式错误、截断、内容过滤、超预算均为失败，不删除。

真实运行上限为 50 次生成、150000 tokens、无自动重试：1 探针 + 6 抽取 + 最多 36 回答
= 43。供应商价格未知时金额为 null，不从 token 推测人民币。网络执行必须显式 `--execute`，
凭据、原始响应、usage、请求意图与恢复规则沿用已测 live runner，但使用独立运行目录和锁。

## 解释边界

本轮样本作者知道 v1 错误类型，因此只能说前瞻开发诊断，不称盲测。新方法若在这组题上
改善，也可能来自更清楚的状态定义提示，而非结构字段或过滤单独贡献；后续还需分别消融。
一次运行没有随机性区间。引用唯一定位不验证语义蕴含，人工检查发现的问题单独报告。

如果 `scoped_facts` 不优于 `all_facts`，不继续包装“作用域算法已有效”；如果两者都不如
raw，应优先检查抽取损失。即使三组全对，也只能说明题目过易或均可解，不能证明结构获益。
