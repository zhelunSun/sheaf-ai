## 2. 检索的真实结果与接口迁移

`query-support-v4` 保留 v3 严格选择逻辑和数值门槛，只增加检查通路和明确的输出契约。
默认仍 `gate_policy=strict`，门槛默认仍为 0（不启用实验拒绝）。

```text
sheaf search "问题" --min-evidence-score 0.4 --gate-policy review --json
```

HTTP：`GET /search?q=...&min_evidence_score=0.4&gate_policy=review`。
MCP：`sheaf_search(query=..., min_evidence_score=0.4, gate_policy="review")`。
review 必须显式设置正门槛；仅为 `unsupported_modifiers`、健康直接 Entry 语义索引、
对象和部分修饰词可匹配且绝对分数过门槛的候选提供检查通路。不覆盖对象错位、缺失对象、
作用域过滤失败、低分或服务降级。它仍可能返回不支持问题前提的资料。

输出字段 `retrieval_gate` 的状态为 `candidates`、`withheld` 或 `review_required`，
`answerability` 均为 `not_assessed`。core 的旧 `retrieval_gate_answerable` 键保留为 null，
不再让一个布尔值暗示“已验证可答”；需要判断严格门禁是否通过的调用方改读
`retrieval_gate_passed`。CLI/MCP 展平的条目也带 `_retrieval_gate`。

旧集现已是已知标签回归：严格模式仍误拒 3/16、协议无答案返回 3/8；review 找回这
3 条，但协议无答案返回升至 8/8。恢复候选不是提升自动拒答正确率，更不是幻觉率下降。
新增路径不能作为无人核对的回答授权。下一轮要单独区分正面证据、明确否定、证据不足
和冲突，再测生成答案，而非通过空/非空结果判断真假。

完整数值、逐问题诊断、源码 hash 与表示统计见
[修复回归](../evals/repair-regression/README.md)。历史实验所有文件保持不变。

## 3. 继续推进产品愿景的收益判断

结论：继续投入有价值，但应投入到“收藏如何帮助完成一类任务”，而不是继续扩大
通用记忆基础设施。以下是基于当前代码缺口和竞品能力的判断，不是市场收入预测。

两个一手产品边界可作参照：Supermemory 的搜索接口已有 memories/documents/hybrid
及记忆版本关系；Mem0 平台的图记忆已有自动实体关联，并将实体信号与语义/BM25 检索
结合。这意味着单纯增加“向量 + 卡片 + 图”难以作为差异证明；也不能反过来宣称这些
产品没有条件或更新能力。这里核对的是产品文档，不是两者开源代码的完整审查。
来源：[Supermemory Search](https://supermemory.ai/docs/api-reference/recall-search/search-memory-entries)、
[Mem0 Platform Graph Memory](https://docs.mem0.ai/platform/features/graph-memory)，2026-09-04 查阅。

| 接下来投入什么 | 面试/技术收益 | 产品收益判断 | 当前建议 |
|---|---|---|---|
| 一个方法选择任务：保留条件、证据，避免选不适用方案 | 高：问题定义、强基线、失败分析和成本均可追问 | 较高的待测收益：直接改变用户决策，而不只是增加卡片 | 优先 |
| 来源变化后，定位受影响结论并提示重查 | 高：依赖追踪、增量策略和正确性/成本取舍 | 潜在中高，但取决于知识被重复使用、来源确实变化 | 在前项证明复用后推进 |
| 知识表示的同预算比较 | 高，但有可能得到“普通文本已足够”的结论 | 中等且不确定：只有减少错误使用或成本才产生收益 | 做实验，不先扩 schema |
| 更一般的图谱、自动发现关联、继续增加站点 | 现阶段边际收益偏低，容易停留在组件介绍 | 需求不清晰，增加抽取和维护成本 | 暂缓广泛开发 |

产品愿景不必缩成“去重工具”。主动收藏表达用户关注和品味；真正可检验的价值是：
同一批来源能否帮助 Agent 更好地选择方案、解释分歧、发现需要补充的证据。三种方向
可以保留，但先验证“选方法/做方案”一项，避免同时增加三个模糊功能。

面试价值与商业价值分开：当前已有可展示的实现、负结果和修复闭环；付费、留存和
相对日常工具的复用收益仍未知。无用户实验能较快筛掉技术上无效的方案，不能验证
付费意愿。不做没有行为数据支撑的增长率、市场规模或收益评分。

## 4. 下一阶段的有限投入

1. 完成 R1 剩余读取契约：治理状态和证据强度解释不在简略输出中静默消失；不自动
   将普通卡升级成有授权的版本卡。
2. 选择一个方法/方案比较任务族。用公开或人工资料构造包含适用条件、版本变化、
   明确否定、证据不足、冲突的任务；按来源包划分开发/留出，避免改写泄漏。
3. R2 同模型同预算比较原文块、条件完整的普通文本卡、最小结构卡。提供相同源信息，
   记录原始响应、错误适用、条件遗漏、证据支持、构建/查询费用；不给结构组更多信息。
4. 在看结果前固定最低可接受改善和成本上限。若普通文本已经足够，保留简单表示，
   不为展示“创新”继续增加结构；若优势只出现在已见模板，不升级为泛化结论。
5. 只有任务收益成立，再进入 R3 增量维护比较：相同证据序列、全量重建对照、误更新、
   无关结论保持和总费用。更广泛的知识挖掘放在其后。

本轮不调用付费 LLM、不下载大模型、不读真实用户库。真实模型实验需要固定具体模型、
可用凭据与预算；没有这些条件时只能完成数据/协议和机制测试，不能伪造实验产物。
