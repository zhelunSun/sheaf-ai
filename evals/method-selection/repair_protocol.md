# 首轮接口故障后的开发诊断修订

状态：查看首轮失败后的协议修正，不是独立复验，不用于宣称算法质量提升。
原 method-selection-v1 输入、gold、runner、锁和实际首轮结果均保持不变。

## 已观察到的问题

2026-09-04，Paratera DeepSeek-V3.2-Instruct 的 6 次抽取均返回完整 JSON 代码块。
原解析器只接受裸 JSON。另外抽取 prompt 未给出允许的方法 ID，却要求解析结果严格为
任务选项 A/B；模型返回了 Method A/Method B。这是生产者与消费者的接口约定缺口。
原文组 12 次方法选择/证据状态均正确，1 次引用无法唯一定位；该引用不修复。
首轮共 19 次请求、7546 tokens，记录保留，不能将被接口阻断的卡片组当成表示无效。

## 本修订预先固定的改变

1. 仅在抽取提示词尾部添加合法 method_id 列表和要求裸 JSON。不提供问题内容、gold、
   正确方法或类别；列表来自已有 options。重新执行六次抽取，不改旧响应的 method_id。
2. 三组使用同一个外层解析规则：只有整个响应恰为一个 json/无语言代码块，且内部已是
   可解析 JSON 时才去掉代码块。附加解释、多个代码块、不完整 JSON 均不修复；不改主张、
   条件、否定、方法 ID、引用。原文响应和转换 hash、类型分别保存。
3. 原文回答请求未改变，按完整 request 相等复用首轮十二个回答。不是重复抽样，不再
   花费十二次调用。文本卡和结构卡来自同一次新抽取，沿用原冻结题目与评分规则。
4. 首轮消耗先扣除，修订只能使用剩余 31 次请求、142454 tokens；正常最多新增六次
   抽取和二十四次卡片回答，两轮总共 49 次请求，不重新开满额预算。
5. 修订源码和协议在新增模型请求前记录 hash。原始返回与用于解析的返回分开保存；
   不让评分器中的 parsed response 冒充未经修改的原始模型文本。

本轮不改否定/缺失/冲突标签，不修引用，不放宽方法选择判定。引用错误仍计失败，但
选择正确率与引用有效率分开报告。格式修复的收益不能称为知识表示算法的收益。

## 输出与后续边界

新目录明确记录 parent manifest、原请求/响应指纹、借用原文回答数量、新增消耗及包含
失败首轮在内的总消耗；独立部署的卡片组承担全部新构建费用，旧故障构建是调试开销。
耗时不当作严格基准：原文与卡片回答发生在两个时段，供应商负载可能变化。

即便三组在十二题上全对，也只证明小试可运行、这些题能被解答，不证明结构卡优于
原文/普通文本。下一轮必须增加不靠原题改写的来源包、长文干扰和条件变化任务，并固定
真实 tokenizer 与同 token 约束；抽取出现的限定语错误应另立抽取评价，不改旧标签。
