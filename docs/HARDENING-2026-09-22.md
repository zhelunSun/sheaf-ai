# 2026-09-22：知识卡片生产链路加固

起点 `063cd98`；本轮不新增产品功能、不改生产默认模型、不调用付费模型、不操作用户知识库。
目标是让“精选来源 → Knowledge Cards → CLI/MCP 复用”更可信，而不是扩大通用记忆平台。
当前仍是 v0.7.0 之后的开发版本，未发布新版本。

## 1. 已完成的改进

| 问题 | 本轮实现 | 验收边界 |
|---|---|---|
| 截断数组中的内部对象被当成完整模型输出 | 只接受完整 JSON 或完整代码围栏；拒绝重复键和非有限数 | 已知无效输出不会变成静默成功；不等于语义正确 |
| 合法空数组、全部无效、部分无效混为一谈 | 统一 `success / empty / partial / error` 与 warnings、拒绝数量 | CLI/MCP/HTTP 共享服务投影，不公开原始模型响应 |
| 超量裁剪及去重留下指向未保存卡片的关联 | 保留可见告警，清理不可用目标；一批卡片一次提交 | 卡片文件内原子，不是卡片与嵌入索引的跨文件事务 |
| 模糊去重吞掉相反结论 | 保存层只折叠精确内容副本，保留否定、条件、版本、新来源差异 | 宁可保留相似卡，不以词重叠推断语义等价 |
| CLI JSON 混入进度文本，缺卡成功退出 | JSON 模式输出单个有效对象；缺卡和错误非零退出；部分完成可识别 | 旧 list 服务保留；新的详细结果入口提供诊断 |
| MCP 错误类型进入存储层 | 服务入口验证参数，MCP 返回 invalid params；HTTP 空参数为 400 | 未增加分页、管理 UI 或新接口类别 |
| LLM 模拟器执行任意 shell 命令 | 固定 Python/CLI argv、命令和参数白名单、固定 URL 样本、独立 data/cwd/home | 不是 OS 沙箱；子进程仍有当前用户权限 |
| 模拟器隐式读取用户配置、替换失败行为 | 明确授权模型环境与付费执行；禁用两处 dotenv 自动读取；失败保留未评分状态 | 本轮只有无网络故障注入，没有新的真实模拟用户结果 |

原有列表返回 API 继续兼容；希望获得完整失败信息的 Python 调用方应使用
`crystallize_cards_result`、`crystallize_topic_result` 或 `crystallize_and_save_result`。
公共结晶结果中的 `success` 表示未整体失败，不表示事实已验证；部分完成仍有
`status=partial`、warnings，CLI 退出 1。整体模型输出错误为 `status=error`，CLI 退出 3，
MCP `isError=true`。HTTP 对已完成但输出无效的模型调用返回 200 与 `success=false`；
传输/内部异常仍走错误响应。

合法 `[]`、来源不足或只有已存在副本可产生 `empty`，并按需要提供原因。
嵌入更新不完整时卡片保留，结果为 `partial`，不能声称卡片和索引共同提交。

## 2. 对旧实验的进一步诊断

新[离线诊断](../evals/output-contract-regression/README.md)从原始收据读取响应，
检查完整请求、来源、manifest、任务×方法×抽样位置与失败分母，不加载答案标签。
旧 v3 的数据、协议、分数和模型响应均未修改。

- 310 条事实中 6 条引文不是逐字原文，分布在两组；另外四组超过 40 条上限。
- 304 条通过机械格式/定位检查，不意味着条件完整、事实类型正确或引文语义支持。
- 假设只隔离坏事实、仍遵守 40 条上限，可用批次会从 3 变成 4，剩余 135 条；
  **没有启用此策略，也没有重新调用模型测效果**。去掉的证据可能正是拒答或冲突的依据。
- 84 个实际答案的决定、方法和状态字段全部形式自洽。旧实验中“理由支持选择、
  最终却拒答”的问题仍需语义检查，不能靠加一个 JSON 校验器宣称解决。

因此本轮的算法进展是减少确定会丢失信息的处理，并把剩余问题定位准确；
不是新一轮正确率提升证明，也不是把旧实验适配器直接换成生产结晶算法。

## 3. 模拟用户与简历表述

`tests/test_product_profiles.py` 是冻结模型响应的离线产品旅程。
`scripts/llm_depth_test.py` 才是生成意图、执行 CLI、模型评判的探索性脚本；
本轮将其作为可审查的仓库文件交付，历史私有报告不随之发布。

默认运行不调用模型。真实运行必须明确 `--execute` 和允许传入的三个环境变量名称；
`--dry-run` 仍会生成模型意图，因此也可能计费。驱动器和被测生产客户端共享明确的
端点/模型配置，但角色不同，不代表独立裁判或模型质量基准。报告注明代码提交、源码
状态、未评分分母，并拒绝覆盖旧报告。它还不是带完整逐请求 token 账本的正式实验执行器。

建议简历第三条写为：

> 通过自动化测试覆盖核心流程与接口契约，设计模拟用户旅程并开展大模型驱动的
> 探索性测试；保留失败记录与可复查实验结果，建立构建、安装验证和回归交付流程。

“真实使用场景”容易被理解为真实用户研究或完整 Agent→MCP 端到端实测，应避免混称。
此外，普通卡片与有版本的治理记录仍是两个入口，不应说所有结晶卡都会自动形成版本历史。
本地文件便于迁移不等于已经通过全部跨版本搬迁测试。

## 4. 验证与一次环境修复

首次完整回归发现 9 项历史冻结数据检查失败：Windows 检出时换行转换破坏了原始哈希。
逐文件比较后，三份文件仅需恢复 LF 即与原 manifest 完全一致；同一历史检索 revision
另有两份原本冻结为 CRLF，因此不能对整个目录一律转换 LF。
本轮补充精确的 Git 字节保留规则，并保存所有文件的原冻结字节。没有重标题目、
修改 gold 内容、更新 manifest 哈希或放宽校验。相关 14 项历史实验测试已通过。

新增批保存正常改变了 `sheaf_cards/base.py`，旧实验的源码锁因此正确拒绝当前版本；
第二次全量回归有 15 项普通 live 执行器单测受此影响。现将单测移至临时副本，使用该
副本的独立源码锁，保留所有校验；另新增 3 项检查历史锁和锁后漂移仍被拒绝。
没有改旧实验锁或执行器。历史 v1 模型重放应使用其原提交，不能把当前产品代码冒充旧代码。

最终验证：

- 全量回归：`1838 passed, 21 skipped`，57.14 秒；跳过项不计为通过。
- Ruff 检查通过，覆盖生产代码、测试、模拟用户脚本和新增离线诊断。
- 核心离线机制检查、历史冻结数据检查及新增诊断报告重放通过。
- sdist / wheel 构建通过；独立新环境中的安装、CLI 与 MCP stdio 冒烟检查通过。
- wheel 内本轮修改的 9 个生产模块与当前源码一致；未发布到 PyPI。
- 本轮新增真实模型调用为 0；不把这些检查解释为新一轮模型质量提升。

## 5. 下一步只推进一项效果验收

优先以**实际生产结晶链路**做小型新样本验收，而不是再修实验适配器后宣称产品变好。
固定模型、提示、来源、预算和评分口径；覆盖否定、条件、版本差异、明确缺测和真实冲突。
比较条件完整的原文与生产卡片；分别统计生成可用性、主张支持、条件保留、错误使用、
构建与查询用量，并报告全部失败。不从自然语言理由中自动改写模型决定。

先做无网络回归，再决定新模型调用；本轮不借安全修复启动付费场景测试。
检索真实 embedding、自动增量动作策略与全量重建比较仍待后续，不并行扩大。
旧库→新安装的引用/历史搬迁验收可作为下一项小型产品检查，图谱、市场、协作继续暂缓。
